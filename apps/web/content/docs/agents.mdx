# AI Agents

Each domain has a dedicated AI agent that handles customer conversations. Configure how it responds, what it can do, and when it escalates.

## Agent Configuration

Go to **Dashboard → Agents** and select your domain.

### Name

What the agent is called in the dashboard, and what visitors see as the
widget's title once the agent has loaded.

### About this business

A short description of what your business does. It is the strongest signal the
agent has about your products, so make it specific:

```
We sell handmade furniture in Accra. We deliver within Greater Accra in 3
working days, and people usually ask about delivery times, fabric, care and
custom orders.
```

### Filter questions

One question per line. They are asked at the start of a conversation, and the
answers are saved with the lead, so you know who you are talking to before
they ask anything:

```
How many employees do you have?
What's your budget range?
When do you need this by?
```

### Which model answers

The model is a deployment setting, not a per-agent one: the dashboard runs on
Gemini, with an OpenRouter model as a fallback when the primary provider is
unavailable. Both are configured with environment variables.

### When the agent cannot help

The agent escalates to a human when it cannot answer, and the conversation
appears in **Dashboard → Conversations** for you to take over. See
[Conversations](/docs/conversations).

## Agent Tools

Your agent has built-in tools:

### Product Lookup

Search your connected database for products:
- Find products by name or description
- Show prices and availability
- Process payments for selected items

### Booking

Schedule appointments:
- Check available time slots
- Create bookings
- Send confirmation emails

### Escalation

Transfer to humans when needed:
- Detect complex issues
- Gather context before transfer
- Notify human agents via email/dashboard

## Agents per Domain

Each domain has one agent, configured in **Dashboard → Agents**. The agent
answers with that domain's knowledge base, tools and products, so two domains
can behave differently while sharing the same platform:

- **Support Agent** — Handles general questions
- **Sales Agent** — Focuses on product sales
- **Booking Agent** — Manages appointments

A domain in a team can be worked on by everyone in that team, according to
their role — see [Teams](/docs/teams).

## Testing Your Agent

Use the widget on a test page: embed it, ask it what you would ask a
customer, and check the answers against your knowledge base. The conversation
then appears in **Dashboard → Conversations**, so you can see exactly what was
sent and what came back.

## Best Practices

1. **Be specific** — Say what you sell, where you deliver, what you don't cover
2. **Keep the knowledge base current** — The agent can only answer from what is there
3. **Use filter questions** — You learn what visitors need before they ask
4. **Watch the escalations** — They show you what the agent could not answer
5. **Test after every change** — Knowledge, products and tools all change what it says
