{/* # Conversations */}

View and manage all chat conversations from the dashboard.

## Conversation List

Go to **Dashboard → Conversations** to see all active and recent chats:

| Column | Description |
|--------|-------------|
| Customer | Visitor's name or email |
| Status | Active, waiting, resolved |
| Agent | Assigned agent |
| Last Message | Preview of last message |
| Time | When last message was sent |

## Conversation Status

| Status | Description |
|--------|-------------|
| Active | Currently in progress |
| Waiting | Waiting for response |
| Resolved | Conversation completed |
| Escalated | Transferred to human |

## Viewing a Conversation

Click a conversation to see:

### Messages
- Visitor messages (left side)
- Agent responses (right side)
- System messages (escalation notices)
- Timestamps for each message

### Context
- Customer profile
- Previous conversations
- Products discussed
- Actions taken

### Actions
- **Reply** — Send a message as the agent
- **Escalate** — Transfer to a human agent
- **Resolve** — Mark as resolved
- **Close** — Close the conversation

## Human Handoff

When the agent can't help:

1. Agent detects it can't answer
2. Agent asks for permission to escalate
3. Visitor agrees
4. Conversation is flagged for human review
5. Human agent picks up the conversation

### Escalation Triggers

Automatic escalation for:
- Billing disputes
- Technical issues beyond agent knowledge
- Complaints
- Request for human agent

### Manual Escalation

Agents can escalate manually:
- Type "Let me connect you with a human"
- Conversation is flagged
- Human agent is notified

## Notifications

### Escalated Conversations Badge

The Conversations icon shows a red count of **open escalated conversations in
the active workspace**. The count comes from the conversation status itself, so
resolving or closing the conversation clears it even if its notification was
never read. Individual conversations still show their own unread-message count
in the list.

### Notification Bell

The header bell tracks unread escalation notifications across all your
workspaces. Clicking one switches to its workspace and opens that conversation.
Opening, replying to, or resolving the conversation marks its notification read.
Use **Mark all read** to clear the bell.

Notifications are short-lived delivery metadata, not a permanent audit log.
They expire after 30 days and the scheduled cleanup job removes expired rows.

### Tab Title

Browser tab shows the unread notification count: `(3) Ziyarn`

### Toast Notifications

In-app toast alerts for new escalations while the dashboard is visible.

### Browser Notifications

Desktop notifications for new escalations while the tab is hidden (requires
permission).

### Sound

Audio alert for new escalations while the tab is hidden (3-note chime).

## Finding a Conversation

The list shows every conversation for your domains, newest first, with its
status and an unread count. Conversations are grouped by domain, and the
conversation list refreshes while you work, so a new escalation shows up
without a reload.

## Best Practices

1. **Monitor active chats** — Respond quickly
2. **Check escalation queue** — Don't leave customers waiting
3. **Review resolved conversations** — Ensure quality
4. **Use canned responses** — Speed up common replies
5. **Track metrics** — Response time, resolution rate

## Analytics

**Dashboard → Analytics** tracks conversation metrics:
- Conversations per day
- Escalation rate
- Most common topics
- Response times
