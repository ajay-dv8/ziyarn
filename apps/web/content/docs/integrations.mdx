# Integrations

Connect external services to Ziyarn, and drive Ziyarn from your own code.

## Available Integrations

### Databases

Connect a database and use its tables as your product catalog. Configure it in
**Dashboard → Integrations**.

- **PostgreSQL** — Neon, Supabase, Railway
- **MySQL** — PlanetScale, Railway
- **MongoDB** — Atlas
- **Convex** — Convex platform

The schema is read on connect, so you can pick which tables and columns become
products. See [Database](/docs/database).

### Payments

- **Paystack** — Card, mobile money and bank transfer checkout
- **Stripe** — International card payments

Both are processed through the platform: the webhook applies the plan to your
domains when a payment succeeds.

### Email

- **Transactional email** — Booking confirmations, cancellations, escalation
  notices, team invites
- **Campaigns** — Marketing emails to a customer segment

Email is sent through the SMTP server the deployment is configured with. If
none is configured, transactional sends are skipped quietly and campaigns
cannot be sent.

## Talking to Ziyarn

The HTTP API is documented in full in the [API Reference](/docs/api-reference).
In short:

- **Public endpoints** — the widget and the visitor-facing booking pages. The
  widget authenticates with a domain's embed secret.
- **Dashboard endpoints** — the endpoints the dashboard itself uses, with the
  signed-in user's session.

There is no API key system and no published SDK yet. If you need to drive
Ziyarn from a backend, the public endpoints plus an embed secret are the
supported route today — and a custom chat interface is a matter of posting to
`/api/chat` and reading the stream back.

## Receiving events

Today the platform receives webhooks rather than sending them:

| Endpoint | From | What it does |
|----------|------|--------------|
| `POST /api/webhooks/stripe` | Stripe | Payment events; a paid plan is applied to your domains |
| `POST /api/webhooks/resend` | Resend | Delivery, bounce and complaint events |

Both verify the provider's signature before acting.

Outgoing webhooks — "tell my server when a conversation is created" — are on
the roadmap. Until then, poll the dashboard endpoints, or use the chat stream
for live conversations.

## Best Practices

1. **Keep the embed secret private** — it authorises your agent, not a person
2. **Handle errors** — a failed request answers with a `code` and a `message`
3. **Respect the plan's limits** — conversations, credits and seats are
   enforced, not just reported
4. **Store credentials securely** — never commit database or mail credentials
