# Widget Integration

Ziyarn ships three widget looks, all installed with one script tag and one `<zy-widget>` element. Classic and Glow are a vanilla JavaScript web component that runs in a Shadow DOM for complete style isolation — zero dependencies, works on any website. Modern Sleek loads its full-screen glass chat in a Ziyarn iframe, so it can use a richer React surface without touching the host page's styles.

## Basic Installation

Add this code before the closing `</body>` tag:

```html
<script defer src="https://ziyarn.vercel.app/widget.js"></script>
<zy-widget
  data-slug="YOUR_DOMAIN_SLUG"
  data-secret="YOUR_EMBED_SECRET"
></zy-widget>
```

Copy the snippet from **Dashboard → Domains → Install** — it already carries the
right slug and secret.

## Configuration Options

| Attribute | Type | Default | Description |
|-----------|------|---------|-------------|
| `data-slug` | string | — | Domain slug (required) |
| `data-secret` | string | — | Embed secret for authentication (required) |
| `data-title` | string | `Chat with us` | Widget header title |
| `data-subtitle` | string | `We usually reply in minutes` | Widget header subtitle |
| `data-color` | string | `#10b981` | Accent color for the launcher, header and visitor messages (CSS hex value). Modern Sleek uses it for the launcher only. |
| `data-position` | string | `bottom-right` | Widget position: `bottom-right` or `bottom-left` |
| `data-variant` | string | `classic` | Widget style: `classic`, `glow`, or `sleek`. |
| `data-api` | string | origin of the script | Backend API URL override for Classic and Glow — only needed when the widget is served from a different host than the API. Modern Sleek always uses the Ziyarn origin. |

`data-slug` is the **slug** shown on the domain page (for example `acme-support`),
not the domain id. There is no `data-greeting` attribute: the welcome message is
written by the agent, not by the embed snippet.

:::warning
The `data-color` attribute expects a CSS hex value (`#10b981`), NOT Tailwind classes like `bg-blue-500`.
:::

## Widget Variants

Ziyarn ships three looks for the widget:

| Variant | Delivery | What it looks like |
|---------|----------|-------------------|
| `classic` | Script | A floating chat bubble in the corner of the page |
| `glow` | Script | An aurora panel with a thinking orb while the agent answers |
| `sleek` | Script + iframe | A centered glass card with live tool activity, over a dimmed page |

Pick one per domain in **Dashboard → Domains → Settings → Widget**. All three
accept `data-variant` on the embed element; an unknown value falls back to
`classic`, so an embed snippet written before variants existed keeps working.
Modern Sleek uses the same `<zy-widget>` tag as the other variants; its script
adds a launcher and opens the chat in a full-screen iframe.

The variant is a plan feature: the **Free plan includes the classic widget
only**. For script-rendered widgets, a domain whose plan no longer includes its
current widget — after a downgrade, for example — falls back to Classic rather
than serving something the account no longer includes. Modern Sleek is
iframe-backed, so if its plan no longer includes it, the iframe shows an
unavailable message instead of silently switching designs.

### Modern Sleek

Modern Sleek is a full-screen glass chat over a dimmed page. It uses the same
install as Classic and Glow:

```html
<script defer src="https://ziyarn.vercel.app/widget.js"></script>
<zy-widget
  data-slug="YOUR_DOMAIN_SLUG"
  data-secret="YOUR_EMBED_SECRET"
  data-variant="sleek"
></zy-widget>
```

The script renders a launcher bubble. Clicking it opens the chat in a
full-screen iframe served by Ziyarn; the chat's close button posts a message
back to the script, which hides the frame again. The iframe stays loaded after
closing, so reopening it keeps the conversation on screen.

Notes:

- Do not add a separate `<iframe>` or click handler; `widget.js` creates both.
- `data-color` and `data-position` style the launcher. The chat surface has a
  fixed palette and layout.
- `data-api` does not change the iframe's API: the iframe is served by, and
  talks to, the same Ziyarn origin as `widget.js`.
- If your site sets a CSP, allow `frame-src https://ziyarn.vercel.app` in
  addition to the script and connect sources below.
- The iframe URL carries the domain secret, exactly like the script's API calls.

## Platform Guides

### HTML / Vanilla JS

The simplest installation. Add the code before `</body>`:

```html
<!DOCTYPE html>
<html>
<head>
  <title>My Website</title>
</head>
<body>
  <!-- Your content -->

  <script defer src="https://ziyarn.vercel.app/widget.js"></script>
  <zy-widget
    data-slug="my-domain"
    data-secret="secret_abc123"
    data-color="#6366f1"
    data-title="Support"
    data-subtitle="How can we help?"
  ></zy-widget>
</body>
</html>
```

### React / Next.js

In React, use `"use client"` and add the widget via `useEffect` or a script tag:

```tsx
"use client";

import { useEffect } from "react";

export function ChatWidget() {
  useEffect(() => {
    // Widget auto-initializes from the HTML elements
  }, []);

  return (
    <>
      <script defer src="https://ziyarn.vercel.app/widget.js" />
      <zy-widget
        data-slug="my-domain"
        data-secret="secret_abc123"
      />
    </>
  );
}
```

Add to your root layout:

```tsx
import { ChatWidget } from "@/components/chat-widget";

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        {children}
        <ChatWidget />
      </body>
    </html>
  );
}
```

### Next.js with Script Component

Use Next.js `Script` component for optimal loading:

```tsx
"use client";

import Script from "next/script";

export function ChatWidget() {
  return (
    <>
      <Script
        src="https://ziyarn.vercel.app/widget.js"
        strategy="lazyOnload"
      />
      <zy-widget
        data-slug="my-domain"
        data-secret="secret_abc123"
      />
    </>
  );
}
```

### Vue / Nuxt

In Vue, use `<ClientOnly>` to prevent SSR issues:

```vue
<template>
  <ClientOnly>
    <script defer src="https://ziyarn.vercel.app/widget.js"></script>
    <zy-widget
      data-slug="my-domain"
      data-secret="secret_abc123"
    />
  </ClientOnly>
</template>

<script setup>
const apiUrl = import.meta.env.VITE_API_URL;
</script>
```

For Nuxt, add to `app.vue` or a layout:

```vue
<template>
  <NuxtPage />
  <ClientOnly>
    <script defer src="https://ziyarn.vercel.app/widget.js"></script>
    <zy-widget
      data-slug="my-domain"
      data-secret="secret_abc123"
    />
  </ClientOnly>
</template>
```

### Svelte / SvelteKit

Use `onMount` to ensure client-side rendering:

```svelte
<script>
  import { onMount } from "svelte";

  let mounted = false;

  onMount(() => {
    mounted = true;
  });

{#if mounted}

  <zy-widget
    data-slug="my-domain"
    data-secret="secret_abc123"
  />

```

## Middleware / CSP Configuration

If your site uses Content Security Policy headers, you need to allow the widget domain. Classic and Glow need `script-src` and `connect-src`; Modern Sleek also needs `frame-src` for the iframe origin.

### Next.js Middleware

```typescript
// middleware.ts
import { NextResponse } from "next/server";

export function middleware(request) {
  const response = NextResponse.next();
  
  response.headers.set(
    "Content-Security-Policy",
    "default-src 'self'; script-src 'self' https://ziyarn.vercel.app; connect-src 'self' https://ziyarn.vercel.app; frame-src https://ziyarn.vercel.app; style-src 'self' 'unsafe-inline';"
  );
  
  return response;
}
```

### Nginx

```nginx
add_header Content-Security-Policy "default-src 'self'; script-src 'self' https://ziyarn.vercel.app; connect-src 'self' https://ziyarn.vercel.app; frame-src https://ziyarn.vercel.app; style-src 'self' 'unsafe-inline';";
```

### Apache

```apache
Header set Content-Security-Policy "default-src 'self'; script-src 'self' https://ziyarn.vercel.app; connect-src 'self' https://ziyarn.vercel.app; frame-src https://ziyarn.vercel.app; style-src 'self' 'unsafe-inline';"
```

### Cloudflare Workers

```javascript
addEventListener("fetch", (event) => {
  const response = await fetch(event.request);
  response.headers.set(
    "Content-Security-Policy",
    "default-src 'self'; script-src 'self' https://ziyarn.vercel.app; connect-src 'self' https://ziyarn.vercel.app; frame-src https://ziyarn.vercel.app; style-src 'self' 'unsafe-inline';"
  );
  return response;
});
```

## TypeScript Support

```typescript

  interface IntrinsicElements {
    "zy-widget": {
      "data-slug"?: string;
      "data-secret"?: string;
      "data-color"?: string;
      "data-position"?: "bottom-right" | "bottom-left";
      "data-variant"?: "classic" | "glow" | "sleek";
      "data-title"?: string;
      "data-subtitle"?: string;
      "data-api"?: string;
      className?: string;
      style?: React.CSSProperties;

  }
}
```

## Troubleshooting

### Widget doesn't appear

1. Check that the script is loaded (open DevTools → Network tab)
2. Verify `data-slug` and `data-secret` are correct
3. Ensure no CSP headers are blocking the script

### Modern Sleek launcher does not open the chat

1. Check that the element has `data-variant="sleek"` and that `widget.js` loaded
2. Check the browser console for a frame-ancestors or X-Frame-Options error
3. If your site sets a CSP, add `frame-src https://ziyarn.vercel.app`
4. Check the Network tab for a request to `/embed/YOUR_DOMAIN_SLUG`
5. If the frame opens but says the style is unavailable, confirm the domain's
   plan and saved widget style include Modern Sleek

### Widget appears but doesn't respond

1. Check that `data-api` (if you set one) points to your backend URL
2. Verify the backend is running and accessible
3. Check browser console for CORS errors

### Styles conflict with my site

The widget runs in a Shadow DOM, so styles shouldn't conflict. If you see issues:

1. Check for `all: initial` or `all: revert` in your CSS
2. Ensure no global reset is affecting Shadow DOM elements

### Console errors

Open DevTools → Console tab. Common errors:

- `Failed to fetch` — API URL is wrong or backend is down
- `Unauthorized` — embed secret is incorrect
- `Domain not found` — the slug doesn't exist, or the secret belongs to another domain
