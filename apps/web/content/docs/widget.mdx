# Widget Integration

The Ziyarn widget is a vanilla JavaScript web component that runs in a Shadow DOM for complete style isolation. It has zero dependencies and works on any website.

## Basic Installation

Add this code before the closing `</body>` tag:

```html
<script defer src="https://ziyarn.vercel.app/widget.js"></script>
<zy-widget
  data-slug="YOUR_DOMAIN_SLUG"
  data-secret="YOUR_EMBED_SECRET"
></zy-widget>
```

Copy the snippet from **Dashboard → Domains → Install** — it already carries the
right slug and secret.

## Configuration Options

| Attribute | Type | Default | Description |
|-----------|------|---------|-------------|
| `data-slug` | string | — | Domain slug (required) |
| `data-secret` | string | — | Embed secret for authentication (required) |
| `data-title` | string | `Chat with us` | Widget header title |
| `data-subtitle` | string | `We usually reply in minutes` | Widget header subtitle |
| `data-color` | string | `#10b981` | Accent color for the launcher, header and visitor messages (CSS hex value) |
| `data-position` | string | `bottom-right` | Widget position: `bottom-right` or `bottom-left` |
| `data-variant` | string | `classic` | Widget style: `classic` or `glow` |
| `data-api` | string | origin of the script | Backend API URL override — only needed when the widget is served from a different host than the API |

`data-slug` is the **slug** shown on the domain page (for example `acme-support`),
not the domain id. There is no `data-greeting` attribute: the welcome message is
written by the agent, not by the embed snippet.

:::warning
The `data-color` attribute expects a CSS hex value (`#10b981`), NOT Tailwind classes like `bg-blue-500`.
:::

## Widget Variants

Ziyarn ships two looks for the widget:

| Variant | What it looks like |
|---------|-------------------|
| `classic` | A floating chat bubble in the corner of the page |
| `glow` | An aurora panel with a thinking orb while the agent answers |

Pick one per domain in **Dashboard → Domains → Settings → Widget**, or set
`data-variant` on the embed element. An unknown value falls back to `classic`,
so an embed snippet written before variants existed keeps working.

The variant is a plan feature: the **Free plan includes the classic widget
only**. If a domain's plan does not include its current widget — after a
downgrade, for example — the widget falls back to Classic rather than serving
something the account no longer includes.

## Platform Guides

### HTML / Vanilla JS

The simplest installation. Add the code before `</body>`:

```html
<!DOCTYPE html>
<html>
<head>
  <title>My Website</title>
</head>
<body>
  <!-- Your content -->

  <script defer src="https://ziyarn.vercel.app/widget.js"></script>
  <zy-widget
    data-slug="my-domain"
    data-secret="secret_abc123"
    data-color="#6366f1"
    data-title="Support"
    data-subtitle="How can we help?"
  ></zy-widget>
</body>
</html>
```

### React / Next.js

In React, use `"use client"` and add the widget via `useEffect` or a script tag:

```tsx
"use client";

import { useEffect } from "react";

export function ChatWidget() {
  useEffect(() => {
    // Widget auto-initializes from the HTML elements
  }, []);

  return (
    <>
      <script defer src="https://ziyarn.vercel.app/widget.js" />
      <zy-widget
        data-slug="my-domain"
        data-secret="secret_abc123"
      />
    </>
  );
}
```

Add to your root layout:

```tsx
import { ChatWidget } from "@/components/chat-widget";

export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        {children}
        <ChatWidget />
      </body>
    </html>
  );
}
```

### Next.js with Script Component

Use Next.js `Script` component for optimal loading:

```tsx
"use client";

import Script from "next/script";

export function ChatWidget() {
  return (
    <>
      <Script
        src="https://ziyarn.vercel.app/widget.js"
        strategy="lazyOnload"
      />
      <zy-widget
        data-slug="my-domain"
        data-secret="secret_abc123"
      />
    </>
  );
}
```

### Vue / Nuxt

In Vue, use `<ClientOnly>` to prevent SSR issues:

```vue
<template>
  <ClientOnly>
    <script defer src="https://ziyarn.vercel.app/widget.js"></script>
    <zy-widget
      data-slug="my-domain"
      data-secret="secret_abc123"
    />
  </ClientOnly>
</template>

<script setup>
const apiUrl = import.meta.env.VITE_API_URL;
</script>
```

For Nuxt, add to `app.vue` or a layout:

```vue
<template>
  <NuxtPage />
  <ClientOnly>
    <script defer src="https://ziyarn.vercel.app/widget.js"></script>
    <zy-widget
      data-slug="my-domain"
      data-secret="secret_abc123"
    />
  </ClientOnly>
</template>
```

### Svelte / SvelteKit

Use `onMount` to ensure client-side rendering:

```svelte
<script>
  import { onMount } from "svelte";

  let mounted = false;

  onMount(() => {
    mounted = true;
  });
</script>

{#if mounted}
  <script defer src="https://ziyarn.vercel.app/widget.js"></script>
  <zy-widget
    data-slug="my-domain"
    data-secret="secret_abc123"
  />
{/if}
```

### Angular

In Angular, add to your main component and configure `CUSTOM_ELEMENTS_SCHEMA`:

```typescript
// app.component.ts
import { Component } from "@angular/core";

@Component({
  selector: "app-root",
  template: `
    <script defer src="https://ziyarn.vercel.app/widget.js"></script>
    <zy-widget
      data-slug="my-domain"
      data-secret="secret_abc123"
    ></zy-widget>
  `,
})
export class AppComponent {}
```

```typescript
// app.module.ts
import { NgModule, CUSTOM_ELEMENTS_SCHEMA } from "@angular/core";

@NgModule({
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
  // ...
})
export class AppModule {}
```

## Middleware / CSP Configuration

If your site uses Content Security Policy headers, you need to allow the widget domain.

### Next.js Middleware

```typescript
// middleware.ts
import { NextResponse } from "next/server";

export function middleware(request) {
  const response = NextResponse.next();
  
  response.headers.set(
    "Content-Security-Policy",
    "default-src 'self'; script-src 'self' https://ziyarn.vercel.app; connect-src 'self' https://ziyarn.vercel.app; style-src 'self' 'unsafe-inline';"
  );
  
  return response;
}
```

### Nginx

```nginx
add_header Content-Security-Policy "default-src 'self'; script-src 'self' https://ziyarn.vercel.app; connect-src 'self' https://ziyarn.vercel.app; style-src 'self' 'unsafe-inline';";
```

### Apache

```apache
Header set Content-Security-Policy "default-src 'self'; script-src 'self' https://ziyarn.vercel.app; connect-src 'self' https://ziyarn.vercel.app; style-src 'self' 'unsafe-inline';"
```

### Cloudflare Workers

```javascript
addEventListener("fetch", (event) => {
  const response = await fetch(event.request);
  response.headers.set(
    "Content-Security-Policy",
    "default-src 'self'; script-src 'self' https://ziyarn.vercel.app; connect-src 'self' https://ziyarn.vercel.app; style-src 'self' 'unsafe-inline';"
  );
  return response;
});
```

## TypeScript Support

The widget is a vanilla JS web component. For TypeScript support, add this to your project:

```typescript
// ziyarn-widget.d.ts
declare namespace JSX {
  interface IntrinsicElements {
    "zy-widget": {
      "data-slug"?: string;
      "data-secret"?: string;
      "data-color"?: string;
      "data-position"?: "bottom-right" | "bottom-left";
      "data-variant"?: "classic" | "glow";
      "data-title"?: string;
      "data-subtitle"?: string;
      "data-api"?: string;
      className?: string;
      style?: React.CSSProperties;
    };
  }
}
```

Or use the global declaration:

```typescript
// global.d.ts
declare global {
  namespace JSX {
    interface IntrinsicElements {
      "zy-widget": {
        "data-slug"?: string;
        "data-secret"?: string;
        "data-color"?: string;

        "data-variant"?: "classic" | "glow";
        "data-title"?: string;
        "data-subtitle"?: string;
        "data-api"?: string;
      };
    }
  }
}

export {};
```

## Troubleshooting

### Widget doesn't appear

1. Check that the script is loaded (open DevTools → Network tab)
2. Verify `data-slug` and `data-secret` are correct
3. Ensure no CSP headers are blocking the script

### Widget appears but doesn't respond

1. Check that `data-api` (if you set one) points to your backend URL
2. Verify the backend is running and accessible
3. Check browser console for CORS errors

### Styles conflict with my site

The widget runs in a Shadow DOM, so styles shouldn't conflict. If you see issues:

1. Check for `all: initial` or `all: revert` in your CSS
2. Ensure no global reset is affecting Shadow DOM elements

### Console errors

Open DevTools → Console tab. Common errors:

- `Failed to fetch` — API URL is wrong or backend is down
- `Unauthorized` — embed secret is incorrect
- `Domain not found` — the slug doesn't exist, or the secret belongs to another domain
